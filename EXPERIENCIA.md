A lo largo de la exploración de GitHub y de la actividad, me resultaron muy confusos conceptos como commit, branch, push, pull request y merge.
No tenía claro qué hacía cada uno ni cómo se conectaban dentro del flujo de trabajo.
Ahora tengo entendido que:
Un commit registra los cambios hechos junto con un mensaje descriptivo.
Una branch permite trabajar en una versión paralela del proyecto, ideal para desarrollar nuevas funciones sin alterar la versión principal.
Un pull request es la solicitud de revisión e integración de los cambios en la rama principal.
El merge combina los cambios de distintas ramas.
De igual forma, el apartado de issues me pareció muy útil para organizar tareas pendientes, errores detectados y hacer seguimientos de ellos.

En pocas palabras, el uso de GitHub me permitió documentar el avance del proyecto y mantener un historial claro de los cambios realizados, lo cual considero un aprendizaje fundamental para futuros desarrollos.
